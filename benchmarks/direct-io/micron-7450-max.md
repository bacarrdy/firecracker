# Micron 7450 MAX with hardware power-loss protection

This repeats the [KC2500 SG32 fio matrix](fio.md) on a 3.2 TB Micron 7450 MAX. Both modes used the same Firecracker `97174a4368639848431d0c67d841d70714b6d736` executable, Async, Writeback, PCI, and a fully allocated 1 GiB raw file on ext4. Host Linux was `7.0.0-43-generic`. The guest had Linux 6.1.191, one vCPU, 384 MiB of RAM, 4096-byte logical blocks and fio 3.43 with libaio. All 12 boots negotiated 32 data segments. The backing file had one descriptor, with `O_DIRECT` set in the direct runs. [Micron specification](https://assets.micron.com/adobe/assets/urn%3Aaaid%3Aaem%3Ad133a40b-b36c-4b17-b768-659acc4d4bca/original/as/7450-nvme-ssd-tech-prod-spec.pdf)

The matrix has 396 completed phases with three paired seeds (61441–61443) and both guest cache settings. Each of the 504 read or write samples transferred the same number of bytes as the corresponding archived KC2500 sample. Random jobs use QD32 and 256 MiB, except the two QD1 4 KiB jobs that use 8 MiB. Sequential 512 KiB and 1 MiB jobs use QD16 and 256 MiB. The 8 KiB mix is 70% reads and the other mixes are 50% reads. Pair order alternates and the backing file is advised `POSIX_FADV_DONTNEED` between phases. The KC2500 figures came from a workstation with a different host kernel, so cross-host figures reflect the full storage configuration.

Each data cell gives the median of three trials as active fio MiB/s / IOPS / data-operation p99 in ms. The final guest fsync is timed separately. The last column divides bytes by the sum of the fio job time and final fsync time for each sample, then takes the median. In-job fsyncs are already part of the fio job time. Bold marks the better displayed value within each row. [All Micron samples](micron-7450-max-fio-samples.csv)

On the Micron, direct improved both active rate and p99 in 38 of 42 rows with guest cache bypassed and 27 of 42 with guest cache enabled. It had higher rate through final fsync in all 31 write and mixed-direction rows for each guest cache setting. With guest caching enabled, 4 KiB mixed p99 went from 3.391/3.260 ms to 6.521/5.931 ms (read/write). The extra 64 MiB cached read left about 73 MiB resident for the backing file in buffered mode and zero in direct mode. Guest cache growth was about 65 MiB in both modes.

With guest cache bypassed, the QD1 4 KiB job syncing between writes reached 5,769 IOPS buffered and 5,868 direct, versus 160 and 168 on the archived KC2500 workstation. On the Micron the in-job sync p99 was 0.208 ms and 0.214 ms respectively. These are guest completion measurements.
